# Programming Fundamentals with Python

A beginner-friendly, nine-unit course for learning to think like a programmer and write useful Python 3 programs. No prior programming experience is required. The lessons introduce practical Python alongside ideas—decomposition, tracing, testing, and problem solving—that carry over to other languages.

## Learning outcomes

By the end, you should be able to:

- Use variables, expressions, statements, functions, conditionals, loops, and core data structures.
- Design, write, test, and explain small Python programs that solve defined problems.
- Read documentation and experiment safely with unfamiliar language features.
- Break a problem into steps, trace execution, and improve a solution when it fails.

## How to use this course

Work through one unit per week. Read the lesson, type and run the examples (do not just copy them), complete the practice tasks, and explain your reasoning in your own words. Try each exercise before looking at its suggested solution. Save your work in a separate `.py` file for each unit.

Install Python 3 from [python.org](https://www.python.org/downloads/) or use a browser-based Python environment. In a terminal, check the installation with `python --version` (on some systems use `python3 --version`). Run a file with `python filename.py` or `python3 filename.py`.

## Suggested weekly routine

1. Read the unit and run every example.
2. Make a prediction before running each code sample; compare your prediction with the result.
3. Complete the practice without looking at the suggested answers first.
4. Test normal, boundary, and invalid inputs. Record what you learned from mistakes.
5. Explain one concept to a classmate or in a short learning journal.
6. Take a self-quiz; use incorrect answers to choose what to review.

## Beginner habits that pay off

- Indentation is part of Python syntax. Use four spaces per indentation level.
- Read error messages from the bottom upward; the final line often names the error, and the traceback points to where it occurred.
- Change one thing at a time when debugging. Use `print()` to inspect values, then remove temporary diagnostics.
- Give variables and functions descriptive names. Prefer `total_price` over `x` when the meaning is known.
- Make small functions that do one clear job. Test them with several inputs.
- Never assume an input is valid just because it worked once.
